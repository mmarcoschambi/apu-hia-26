# =============================================================================
# CRONTAB LOCAL  -  WSL2 Ubuntu
# Propósito: Automatizar el sync diario del VPS al laboratorio local.
#            Corre todos los días hábiles a las 11:15 ARG (= 10:15 NY).
#            A esa hora el premarket del VPS (08:30 NY) ya corrió, el mercado
#            abrió (09:30 NY) y los snapshots de Finviz del día están listos.
#
# Después del sync, automáticamente:
#   - Se crea una copia fría del snapshot en data/backups/snapshots/
#   - Se valida la integridad del snapshot (estructura JSON, tickers mínimos)
#   - Si la validación falla, se notifica y aborta
#
# INSTALACIÓN:
#   1. Abrir terminal WSL2
#   2. Ejecutar:  crontab -e
#   3. Pegar las líneas de abajo (sin el #)
#
# IMPORTANTE PARA WSL2:
#   El cron de WSL2 NO se inicia automáticamente. Hay dos opciones:
#   A) Iniciarlo manualmente al abrir WSL: sudo service cron start
#   B) Agregarlo al ~/.bashrc o ~/.profile:
#      [[ $(service cron status) != *running* ]] && sudo service cron start
#
#   Para que sudo no pida contraseña al iniciar cron, agregar a /etc/sudoers:
#      tu_usuario ALL=(ALL) NOPASSWD: /usr/sbin/service cron start
# =============================================================================

# Zona horaria del cron (ajustar si tu WSL usa UTC)
CRON_TZ=America/Argentina/Buenos_Aires

# ── LUNES A VIERNES 11:15 ARG (= 10:15 NY) ─────────────────────────────────
# Sync diario de toda la data de investigación del VPS
# 10:15 NY → premarket (08:30) ya corrió, mercado abierto (09:30)
15 11 * * 1-5 cd /home/marcos/trade/momentum-v2 && bash sync_from_vps.sh >> logs/sync_daily.log 2>&1

# =============================================================================
# VERIFICACIÓN:
#   Ver que el cron está corriendo:  service cron status
#   Ver logs del sync:               tail -f logs/sync_daily.log
#   Listar crons activos:            crontab -l
# =============================================================================
