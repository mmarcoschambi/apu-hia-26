🔍 CAUSA RAÍZ:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Look-ahead bias en cálculo de RVOL:
• El método .rolling(20) incluía la barra actual en el promedio
• Esto inflaba artificialmente el RVOL al generar la señal
• El trade record calculaba correctamente (sin look-ahead)
• Resultado: inconsistencia entre señal de entrada y registro

🛠️ SOLUCIÓN IMPLEMENTADA:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. ✅ CORREGIDO CÁLCULO RVOL (daily_engine.py)
   ────────────────────────────────────────────
   ANTES: avg_volume_20 = df['volume'].rolling(window=20).mean().iloc[-1]
   
   AHORA: prior_bars = df[df.index < today]
          avg_volume_20 = prior_bars['volume'].tail(20).mean()
   
   → Elimina look-ahead bias completamente
   → RVOL ahora se calcula con datos históricos solamente

2. ✅ AGREGADAS COLUMNAS DE CONTEXTO (app.py)
   ────────────────────────────────────────────
   Nuevas columnas en exportaciones CSV:
   • context_rvol  → Formato "1.39x" para verificación
   • context_trend → "Uptrend" o "Weak"
   
   → Permite auditoría inmediata de por qué trades entraron/rechazaron
   → Exportaciones ahora incluyen datos de decisión

3. ✅ VERIFICADO FILTRO EXISTENTE (triad_protocol.py)
   ────────────────────────────────────────────────────
   El filtro YA estaba implementado desde el inicio:
   
   if rvol < 1.5:
       return Signal(action='NO_SETUP', 
                     reasoning='REJECTED Blue Sky: RVOL too low')
   
   → Filtro funcionará correctamente ahora con RVOL correcto
